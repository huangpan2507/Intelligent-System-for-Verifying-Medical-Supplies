# 核心流程前四个节点配置体验设计

日期：2026-10-14。对象：髋膝关节正常核心流程（数据库＋API，精简11节点）。
状态：用户已确认 Q42—Q43，并随后明确授权修改代码和运行画布；现已实施并完成本次范围验收。实施结果、测试证据与验证边界见 [实施记录](CORE-FIRST-FOUR-CONFIGURATION-IMPLEMENTATION.md)。本文记录设计依据。

## 范围及已有约定

优化 Task Start、Settlements、SettlementChecks、Classification 的信息层级及编辑布局。延续 Studies 的折叠摘要、紧凑编辑与宽编辑区域；按各节点的业务操作组织，不统一塞进相同的六个分组。

保留已有任务入参只读、真实字段选择、查询范围、身份检查、规则优先与模型辅助、输出状态和统计口径。当前画布仍为11节点。本轮不扩展异常处理，也不重新引入已舍弃的旧配置方式。

设计时的事实依据：前端组件、后端契约与校验实现，以及上轮已验收的 `evidence/lookup-configuration-20261014/graph.json`。设计阶段未重新执行任务；随后实施阶段的新任务、页面测试及运行图核对另见实施记录，不以历史结果替代新验收。

## 已核实的问题

- CanvasConfiguration 仅允许 databaselookup 使用宽编辑区，其余节点仍是 w-96 窄面板。
- TaskInputPanel 将三个参数和六个任务上下文字段合并成九张同级卡片。Task Start 的配置为空对象；它应展示输入，不应变成参数定义编辑器。
- Settlements、SettlementChecks 仍通过递归 SchemaForm 展示后端结构；重复边框、逐项删除按钮及竖排子配置拉长页面。
- Classification 已有专用编辑器，但字段、类别、规则、模型主体仍连续展开。字典准备中混有结果前缀；事实冲突核对放在模型高级设置里，与接口路径、调用上限同层。
- SettlementChecks 当前配置是14个必填字段、3个身份字段、2条数值条件。CNT、PRIC 条件为 ≥0。当前必填逻辑检查 NULL，不等同于已检查所有空字符串或空白文本。
- 身份 Name、Namespace 参与内部身份值组成，不能在重命名节点时重新生成，也不是无关紧要的显示标签。

## 共用布局原则

1. 顶部保留节点名、业务用途、上游来源；提供窄面板／宽编辑切换。宽编辑沿用画布内扩展面板，编辑同一份草稿，切换宽度不新增一套保存状态。
2. 每组标题说明业务问题；摘要来自实际配置。折叠时保留数量、关键条件、未配置状态及错误数。点击错误可展开定位，不能靠折叠隐藏错误。
3. 宽区域采用行列编辑，窄区域自动换为两行；不缩小字号，不迫使表单横向滚动。真实数据预览表可以独立滚动。
4. 字段多选使用可搜索列表和已选项；长字段可查看完整来源、名称、类型。字段别名不冒充数据库原字段。
5. 接口路径、内部身份等技术细节下沉；影响业务结论的条件、冲突判断不能仅因为复杂就藏进技术高级参数。
6. 已配置节点默认展开主要操作组，其余显示摘要；新节点或出错节点展开需要完成、修正的组。配置摘要与实际运行结果明确区分，无任务不显示通过或已分类。
7. 节点切换、宽度切换和折叠不串值、不丢草稿。保留真实元数据与失效引用提示，不能静默选取同名字段替换来源。

## 1. Task Start：查看这次任务要求什么

| 层级 | 内容 | 展示方式 |
| --- | --- | --- |
| 任务选择 | 未选择任务／具体任务；加载与错误状态 | 顶部常驻，不自动把最近任务视为本次任务 |
| 业务入参 | 医院、开始时间、结束时间、规则名称 | 默认展开，只读紧凑键值表；日期作为一个期间展示，但保留两个真实字段 |
| 任务追溯 | 监管编号、平台任务编号、绑定版本 | 折叠摘要；编号可完整查看和复制 |
| 接口与技术详情 | scheme、release_id、字段名和类型、参数与上下文区别 | 默认折叠，只读；rule_name 是已受理任务上下文，不能改写成第四个查询参数 |
| 输出说明 | 向下游提供医院和期间参数，并保留任务上下文 | 简短说明，测试请求仍在独立入口提交 |

未选择任务时显示输入契约及“尚未接收”；已选择任务但数据缺失时显示缺失状态，不将其解释为没有选择任务。选择中的任务加载失败不显示上一任务的值。可见标题需区分任务输入查看与配置编辑。

## 2. Settlements：从哪里读取、读取哪些记录

| 分组 | 配置与摘要 |
| --- | --- |
| 数据来源 | 连接 → Schema／数据库 → 表；当前 public.core_flow_settlement_v1；按数据库类型解释范围 |
| 读取范围 | 一个条件编辑表，区分“任务参数”和“固定值”来源。医院与期间3条、医保／耗材／非退费3条；行内保留业务说明 |
| 数据预览与输出 | 默认折叠，查看输出字段与样本；说明条件筛选记录，表读取返回全部源字段，并通过数据集交给下游 |
| 高级读取设置 | SQL、SQL绑定参数、结果字段依据和时区等；只呈现当前读取方式适用的配置，并明确哪些配置实际生效 |

当前六条条件保持为同一组 AND 条件，不能因为视觉分组改变组合逻辑。优先在同一表内用来源标记区分，避免把两套字段列表写回后端导致顺序或值类型改变。常量字符串“1”“301”和数字0保持原有类型。

普通表读取不并排展示空 SQL、空参数列表和手写结果字段表。具备 SQL 配置时必须显著显示 SQL 读取状态，不得把实际生效的 SQL 隐藏为“未使用”。切换模式不能偷偷删除原配置或让互相冲突的两套配置同时被视为生效。

现有预览参数 JSON 编辑器放入预览组内的调试详情，并标明是本次预览绑定值，不是 Task Start 已收到的任务入参。本轮不增加自动提交任务或选择任务后自动查询数据库的行为。

## 3. SettlementChecks：确认数据是否具备处理条件

| 分组 | 配置与摘要 |
| --- | --- |
| 必要信息 | 14个必填字段，使用可搜索多选；说明当前缺失检查针对 NULL |
| 同一明细的认定 | ORGAN_CODE＋DATA_SOURCE＋SETL_FEE_LIST_ID；明确是认定同一明细，不是业务范围筛选 |
| 基础数值与条件 | 紧凑条件行：CNT ≥0、PRIC ≥0；仍允许通用节点配置其他质量条件。可选的严格唯一约束置于本组的展开子区 |
| 结果处理说明 | Valid 继续；Issues 区分数据错误、事实冲突与已合并重复提示；处理方式为只读说明，不创造尚不存在的策略开关 |
| 技术详情 | 系统管理的内部身份 Name／Namespace，只读展示（Q43 已确认） |

业务条件不因布局优化改变。必填列表中的 OP_EM_MARK 表示该字段需要有值，不表示要求住院，更不等于重新加入 OP_EM_MARK=3 的范围限制。

Q43 已确认沿用 Q39 的设计原则：只让使用者选择真实身份字段，Name／Namespace 系统管理并只读。现有有效值 settlement_detail/core-flow-v1 保持；新节点生成稳定标识并持久保存，改节点显示名不改变标识。实施范围包括配置初始化和保存行为，不只是隐藏输入框或调整 CSS。

通用 Validate 可以只做质量检查，不强制所有节点启用身份处理。当前核心模板继续启用；编辑身份字段时不能因暂时清空选择就重置内部标识，缺少必要字段应明确提示。严格唯一约束（unique）会把同键重复作为错误，而 identity 允许完全重复合并；二者不能合并为同一开关或相互自动转换。当前核心模板没有配置 unique，子区摘要显示未启用，有配置时必须显示。

## 4. Classification：依据什么、怎样判断、往哪里走

| 分组 | 内容及默认摘要 |
| --- | --- |
| 分类依据 | 字段＋用途紧凑表，3个依据字段、2个辅助上下文字段；两者均供模型使用，依据引用要求保持 |
| 类别与去向 | 人工髋关节→继续、人工膝关节→继续、其他→排除；无法确定是系统状态，单独说明 |
| 判断规则与复核 | 2条公共字段规则，任一依据字段内含全部关键词；单条覆盖、适用条件按需展开；歧义提示与事实冲突核对归入此组 |
| 模型辅助 | 模型连接、模型名称、业务说明；摘要解释何时调用；完整自动生成指令可展开查看；接口路径与调用上限放技术子区 |
| 结果与技术详情 | Data／Issues 去向说明、输出字段、结果前缀；既有实际前缀保留，修改需提示下游引用影响 |

默认展开分类依据与判断规则，类别和模型折叠但摘要可见；“需配置模型”“使用自定义字段”“存在冲突核对”等重要状态不能被折叠掩盖。规则组可在摘要显示已配置类别，避免编辑规则时看不到合法类别。

字典解释属于可选的输入准备，放入“分类依据”的子区。第四节点未启用字典时仅显示轻量入口；StudyRelevance 使用同一节点能力，已启用时展示字典、代码字段、版本来源和生成字段。不能为了耗材节点简洁而删除字典、按目标条件匹配、结果前缀等复用能力。

歧义提示不等于已确认事实冲突：前者可交模型进一步判断，后者不能仅因模型自报高置信度就放行。conflicts 从技术高级区移出只改变信息层级，不改变其判定时机。置信度仍用于展示，未命中规则仍不能直接视为其他。
