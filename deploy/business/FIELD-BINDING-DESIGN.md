# Business 配置阶段的字段发现与绑定

## 已确认的目标与边界

业务字段引用必须有明确来源。映射可以给已有字段另取名称；明确的计算、常量和汇总规则也可以定义输出字段。仅填写一个名称，或给不存在的来源字段改名，不能构成有效引用。

下游节点引用其连线所指向的上游输出端口；原始数据源具有某字段，不意味着经过投影、映射、关联或汇总后该字段仍以原名称可用。

配置阶段可以读取数据库结构、单独预览 SQL 或测试 API，而无需启动整个工作流。结构推导和实际处理业务记录是不同活动。

| 决定 | 用户确认的规则 | 边界 |
|---|---|---|
| Q1：契约作为依据 | API 服务方的响应结构可用于配置字段，即使测试返回空数组；标明契约已声明、样本尚未验证 | 随意手填字段名称不算契约；运行时仍校验。理由见 [ADR 0001](../../docs/adr/0001-business-api-contract-field-binding.md) |
| Q2：配置阶段发现方式 | 选择数据库连接、Schema、表后自动读取列；SQL 和 API 由用户显式点击预览或测试，并提供必要参数 | 不因普通编辑操作自动执行整套工作流 |
| Q3：失效引用 | 已选字段失效时保留草稿与原绑定、明确标错，阻止受影响流程发布和执行，要求重新选择或明确映射 | 不按相似名称自动替换；草稿保存与发布可用性分开。无效草稿不会因此禁用先前仍有效的已发布版本；运行中发现异常沿用既有依赖隔离规则 |
| Q4：依据服务方文档录入 | 没有机器可读结构时，允许在专门的接口契约入口依据服务方文档录入字段、类型、响应记录路径，并保留文档出处 | 标明文档录入，不冒称已实际采样验证；普通字段引用仍从已建立的结构中选择。人工录入可能出错，出处不等于自动验证真实性 |
| Q5：样本作为依据 | 没有服务方契约时，允许从实际响应发现字段，确认类型后用于绑定与发布，明确标注样本依据 | 运行时继续校验；未观察到的字段不能凭空补入，空数组不能生成记录字段。一次样本不保证所有记录结构相同 |
| Q6：测试参数依赖上游 | 首期手工填写测试值或选取已有上游预览记录，不为获取测试值自动运行上游分支或整个工作流 | 不新增自动运行至当前节点的能力；选择已有预览记录不等于自动执行上游 |

## 决策树

```text
配置阶段绑定有来源的业务字段
├─ 字段依据
│  ├─ 数据库真实表结构
│  ├─ Q1 已确认：服务方 API 契约可用，区分是否采样
│  │  └─ Q4 已确认：允许依据文档录入，保留出处并标明来源
│  ├─ Q5 已确认：真实样本发现并确认类型后可用于绑定与发布
│  └─ 上游输出：按连线、输出端口及明确规则推导
├─ Q2 已确认：数据库自动读取，SQL/API 显式预览
│  └─ Q6 已确认：手工测试值或已有预览记录，不自动执行上游
└─ Q3 已确认：失效字段保留草稿，阻止受影响流程发布和执行
   ├─ 沿用既有决定：发布版本不可变，运行失败按依赖影响范围隔离
   └─ 沿用既有语义：响应属性缺失与显式 null 不自动等同
```

六项选择已确认，当前决策树没有待回答分支。下面的工程拆解用于落实这些规则，不表示内部接口或持久化细节已由用户逐项指定；如果实施发现需要改变已确认边界，再明确提出具体冲突。

属性是否必有与值是否可空需要分别表达；实现不得仅因允许 null 就把任意缺失字段当作有效输入。该要求延续既有缺失与 null 不等同的语义，不作为重复确认问题。刷新字段只改变草稿；已发布结构和历史结果保持原版本。

## 实现范围

| 工作项 | 具体行为 | 主要现有位置 |
|---|---|---|
| 数据库字段发现 | 按连接、Schema、表加载真实字段；切换来源后更新候选集合并校验已有绑定；表模式展示读取到的结构，避免误导用户重复手写 Fields | `CanvasConfiguration.tsx`、`connections.py` |
| SQL 预览结构 | 保留显式预览和参数绑定；采用结果列名并提示确认类型；SQL 或来源改变后重新判断旧结构是否仍适用，不沿用无提示的旧预览结果 | `DatabasePreview.tsx`、`connections.py` |
| API 契约配置 | 将来源结构定义与普通字段引用区分；导入可支持的机器可读结构，或按服务方文档录入；保存对应接口、响应记录路径和出处，区分契约与样本依据 | `catalog.py`、`api.py`、画布配置表单 |
| API 显式测试 | 采用节点请求配置与独立测试参数发起有限预览；展示响应并按记录路径发现字段；确认类型后采用。测试参数不替换正式的上游字段绑定 | `sources.py`、`api.py`、画布配置面板 |
| 上游结构与字段引用 | 按实际连线和输出端口传播字段；Join 的左右输入分别选择；映射及派生的新名称作为输出定义，后续节点从推导结构选择；补齐请求体等位置的引用校验 | `SchemaForm.tsx`、`compiler.py`、`catalog.py` |
| 发布与运行校验 | 配置错误可保存草稿，但阻止受影响版本发布和启动；后端同样校验，不能依赖前端下拉防错；运行检查实际结构并区分缺失与 null，沿用版本固定及依赖隔离 | `compiler.py`、`sources.py`、`runtime.py` |

来源证据与所选连接、接口、查询或表结构需要关联，不能把另一个来源的发现结果套用到当前节点。界面应分别显示加载中、发现失败、没有记录和字段失效；一次预览失败或空数组本身不能证明已有字段被删除。API 记录路径与字段提取范围须明确，不承诺自动展开任意嵌套数组。

契约与样本存在明确矛盾时，应指出具体字段和依据供核对，不静默改写已确认结构。合法的可选字段在某条样本中未出现，不自动构成契约冲突；允许省略和允许 null 是不同条件。

## 验收场景

以下是实现的验收要求；已执行的自动化验证与尚未完成的环境验证分别记录在[实现与验证记录](./FIELD-BINDING-IMPLEMENTATION.md)，不能以本地测试代替真实数据库集成验证。

1. 工作流未运行，选择真实数据库表即可下拉列；空表同样可用；相同表名位于不同 Schema 时，候选列与选择的 Schema 一致。
2. SQL 结果使用别名时，下游显示结果列名；修改 SQL 后旧发现结果不会无提示地继续作为有效依据；空结果无法可靠推断的类型明确要求确认。
3. API 有服务方契约、测试返回空数组时，仍可选择契约字段，界面明确显示样本尚未验证。
4. 按文档录入接口结构后，下游可以下拉已录入字段并查看出处；系统不宣称人工录入已经通过真实请求验证。
5. API 没有契约但真实样本有字段时，确认类型后可绑定和发布；空数组不能凭空生成字段；从样本采用字段时不能任意改成未观察到的来源字段名称。
6. API 依赖上游值时，测试可使用手工参数或已有预览记录；不自动执行其他节点，正式绑定保持原样。
7. Transform 的映射输出、Aggregate 的汇总输出、Join 的带前缀输出，无需运行整图即可提供给下游选择；已经被上游移除的原字段不能继续有效引用。
8. 字段确已失效时保留草稿与错误位置，发布和执行入口均阻止受影响配置；直接提交无效引用也会被后端拒绝。草稿失效不改写已有发布版本或历史结果。
9. 响应属性缺失与显式 null 分别处理；被契约允许省略的字段不被误判为结构已删除；运行中违反字段约定时保留原始依据并按依赖范围隔离。
10. 同类节点之间切换、连接或请求配置快速变化时，字段候选和预览结果与当前来源对应，不串用其他节点或旧请求的结果。

## 实施前定位事实

- 数据库元数据读取和普通字段下拉已有实现；前端表列表、列列表请求未传递所选 Schema，需要补齐。
- SQL 预览取得真实结果列名，最多读取 25 行用于预览和推断类型；发布编译当前采用声明字段，不重新执行 SQL 验证。
- API 输出结构当前依赖手工 `fields` 声明，尚无自动读取接口契约或真实响应以发现字段的配置入口。
- 配置检查能推导普通运算节点的输出结构；下游字段下拉基于对应上游端口。源头声明不可靠时，下拉本身不能证明字段真实存在。
- 现有发布检查尚未统一覆盖数据库条件字段、API 请求体中的字段绑定及模型输入字段等引用。
- API 运行读取当前会把缺少的可空字段归一化为 null；它不能可靠区分属性缺失与属性存在但值为空。是否允许省略也不应仅由是否可空推断。
- 现有真实影像接口资料是 [Markdown 契约映射说明](../verification/imaging-api-contract.md)及对应测试中的响应示例，尚未发现对应的本地机器可读契约；模拟服务的 OpenAPI 不能冒充真实供应方契约。现有记录路径和包装对象有明确示例，不据此推定需要支持任意深层数组自动展开。

上述事实记录实施前的缺口，来自 `CanvasConfiguration.tsx`、`SchemaForm.tsx` 和 `business` 后端的 `catalog.py`、`compiler.py`、`connections.py`、`sources.py`；本轮修复结果见[实现与验证记录](./FIELD-BINDING-IMPLEMENTATION.md)。
